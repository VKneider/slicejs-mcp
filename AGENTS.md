# AGENTS.md — slicejs-mcp

`slicejs-mcp` is the stdio MCP server for Slice.js documentation. It exposes two catalogs:

- **framework** — `VKneider/slicejs_docs`, read from `llm.txt` and the authored Markdown pages.
- **components** — `VKneider/slicejs-components`, read from
  `agent/docs-manifest.json` and each document's `rawUrl`.

## Layout

```text
src/
├── catalogs.ts             # catalog loading, normalization, search, get
├── index.ts                # FastMCP server + tool registration
├── tools/
│   ├── catalog-docs.ts     # namespaced framework/components tools
│   ├── get-doc-content.ts  # legacy framework tools
│   ├── get-llm-full-context.ts
│   ├── list-docs.ts
│   └── search-docs.ts
└── utils.ts
```

`dist/` is generated by `tsc`; never edit it by hand.

## Build and run

Always install from the workspace root:

```bash
pnpm install
pnpm build:mcp
```

Run the server over stdio:

```bash
node dist/index.js
```

There is no unit-test suite yet. After changing catalogs, verify with the workspace MCP tools
(`slice_components_list_docs`, `slice_components_search_docs`, `slice_components_get_doc`) or the
MCP Inspector:

```bash
npx @modelcontextprotocol/inspector node dist/index.js
```

## Rules

1. **Defaults must point at the current repositories.** Components:
   `raw.githubusercontent.com/VKneider/slicejs-components/...`. The old
   `slice.js_visual_library` name is compatibility-only.
2. **Keep the environment overrides working:**
   `SLICE_COMPONENTS_MANIFEST_URL`, `SLICE_COMPONENTS_RAW_BASE_URL`,
   `SLICE_FRAMEWORK_DOCS_BASE_URL`, `SLICE_FRAMEWORK_DOCS_REVISION`.
3. **Do not assume a flat docs folder.** The Components manifest uses `sourcePath` and `rawUrl`;
   nested IDs such as `guides/data-loading` must list, search and resolve.
4. **Do not execute documentation examples** or modify the user's project. The server is read-only.
5. **Preserve tool names and backward compatibility.** The unnamespaced tools (`list_docs`,
   `search_docs`, `get_doc_content`, `get_llm_full_context`) target the framework catalog; the
   `slice_framework_*` and `slice_components_*` tools are the namespaced API.
6. **Update `README.md`, `CHANGELOG.md` and `package.json` version** when behavior changes. Keep
   `files: ["dist"]` and the `prepare` build.
7. **Features** live in `features/` (per the workspace standard). Create one with
   `pnpm feature:new "Title" --area mcp`; do not implement a feature until it is moved to
   `planned`/`in-progress`.
8. Publishing is a release step; do not publish while testing. See the workspace `docs/RELEASE.md`.
